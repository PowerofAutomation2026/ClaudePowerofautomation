Summary

  • Copilot Studio’s new-experience agents (built on the GitHub Copilot harness: Skills, Connected agents, no Topics) can’t be called through Microsoft’s built-in Copilot Studio connector from a code app.
  • Microsoft’s own HTTP with Microsoft Entra ID connectors also fail, with a 403 InsufficientDelegatedPermissions error.
  • What works: a custom connector that signs users in through your own Entra app registration and calls Copilot Studio’s direct conversation endpoints.
  • Result: users pick a harness agent from a drop-down and chat with it, with the current list as context and their own permissions.

The goal

I had built a Power Apps code app that turns any SharePoint list or library into a live dashboard with approvals, e-mail and search. The natural next feature was an AI assistant: pick a Copilot Studio agent, ask “what needs attention right now?”, and have the agent see the list the user is looking at.

Classic agents were easy, because the built-in Microsoft Copilot Studio connector has an Execute Copilot action. Then I created an agent in the new experience: same environment, published, “Authenticate with Microsoft”. The connector couldn’t find it. Agents built on the GitHub Copilot harness run on a different runtime that the classic connector doesn’t speak to.

Wall 1: “There’s an HTTP connector for that”

Copilot Studio has a documented direct-to-engine API, so the obvious idea is a generic HTTP connector. Power Platform ships two: HTTP with Microsoft Entra ID (preauthorized and not). The result:

403 InsufficientDelegatedPermissions
Missing CopilotStudio.Copilots.Invoke

The token needs the delegated permission CopilotStudio.Copilots.Invoke on the Power Platform API. Those connectors sign users in through Microsoft-owned apps, and Entra doesn’t let you grant one Microsoft app consent for another Microsoft API (you’ll see AADSTS65002). A tenant-wide grant script can’t fix that.

Lesson: don’t fight it. Use an app registration you own.

Wall 2: “Fine, a custom connector. But sign-in fails”

A custom connector can use OAuth 2.0 with Azure Active Directory and your own client ID. Create the app registration, add the delegated permission, grant admin consent, create a secret, import a swagger file. Then sign-in fails:

AADSTS50011: The redirect URI
'https://global.consent.azure-apim.net/redirect/new-5fcontoso-20copilot-20direct-5f0123…'
does not match the redirect URIs configured for the application

Every OAuth custom connector gets its own redirect address, so the generic one isn’t enough. Once the connector exists, copy its address from the Security tab (or from the error) and add both:

az ad app update --id $APP_ID --web-redirect-uris `
  "https://global.consent.azure-apim.net/redirect" `
  "https://global.consent.azure-apim.net/redirect/<your-connector-unique-name>"

--web-redirect-uris replaces the whole list, so always pass both.

Wall 3: “Signed in! … 404 RouteNotFound”

Discovery worked on the first call:

GET /copilotstudio/agents/{agent}/conversation-endpoints
→ createConversation + executeTurn URLs

Those URLs are long (/copilotstudio/agenticruntime/3p/…/conversations). My first swagger used one path parameter, /{route}. Custom connectors encode slashes inside a path parameter, so the request left as copilotstudio%2Fagenticruntime%2F… and the service answered RouteNotFound.

The fix: give the connector one operation per segment count — Path4, Path5 … Path12 — each with {s1}/{s2}/…/{sN} as separate path parameters. The app splits whatever URL Copilot Studio returns into segments and picks the matching operation. Slashes stay slashes.

How the calls flow

Text version of the diagram
  1. The app asks the connector to run Discover for the agent’s schema name.
  2. The connector calls Copilot Studio; the answer lists the “create conversation” and “execute turn” URLs.
  3. The app starts a conversation with a PathN operation (N = number of path segments).
  4. The app sends the user’s message with another PathN operation.
  5. Copilot Studio replies with server-sent events; the app merges them into the answer.

The chat helper

About 70 lines of TypeScript. The core idea:

const found = JSON.parse(await call('Discover', { agent: 'cr123_myagent' }))
const start = activities(await post(found.createConversation,
  { emitStartConversationEvent: true }))
const id = start.map(a => a?.conversation?.id).find(Boolean)
const reply = activities(await post(
  found.executeTurn.replace('{conversationId}', id),
  { activity: { type: 'message', text: 'What needs attention right now?',
                conversation: { id } }, conversationId: id }))

post() turns a URL into s1…sN parameters; activities() parses the server-sent events. The full, commented file is in the repository.

Try it yourself

  1. Read the developer guide in the README: ten steps with sample values, from app registration to pac code push.
  2. Run scripts/Setup-CopilotStudioConnector.ps1 -EnvironmentId <your-environment-id> to create the Entra app and the connector.
  3. Create the connection once, run Deploy.cmd (option 2), then add your agent.

Caveats

  • This relies on Copilot Studio’s direct conversation endpoints, which Microsoft may change; regional rollout of the harness runtime is still in progress.
  • An admin who can create app registrations and grant consent is needed, once.
  • It works for published agents set to “Authenticate with Microsoft”.

If this saved you a day of AADSTS errors, share it with someone building code apps.
